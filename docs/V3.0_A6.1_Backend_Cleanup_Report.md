### 7.3 首个管理员初始化流程（建议）

- 不使用明文 SQL 插入密码。新增一次性管理命令（如 `python -m app.scripts.create_admin --username ... --email ...`）：
  1. 复用 `app.core.security.hash_password()`（`pbkdf2_sha256`）生成摘要；
  2. 校验用户名/邮箱唯一，写入 `users`（`role='ADMIN'`、`email_verified_at` 置为当前 UTC、`is_active=1`）；
  3. 强制首次登录改密（或直接生成一次性随机强密码并线下交付）；
  4. 命令幂等：已存在同名管理员则拒绝，不覆盖；
  5. 执行后校验 `role` 并写入一条 `admin_audit_logs`（action 使用既有枚举，不新增取值）。
- 备选：离线 SQL 模板（占位符替换哈希），仅在无法运行应用时使用，执行后立即销毁文件。
- 初始化完成后立即验证：管理员登录 → `GET /admin/*` 返回 200；普通用户访问返回 403；降权后即时失效。

### 7.5 Redis 正式部署方案

1. 独立实例/独立 DB 号，`requirepass` + 仅内网监听，禁止公网暴露。
2. 启用 AOF（`appendonly yes`，`appendfsync everysec`）或 RDB 定时快照，权衡限流窗口丢失的接受度。
3. 内存策略：`maxmemory-policy noeviction`（限流 key 不能被随机驱逐）。
4. key 命名空间保持 `ssp:{DB_NAME}:ai:rate:v2:*`，便于按库隔离与清理。
5. 监控：连接数、`used_memory`、Lua `EVALSHA` 错误率（NOSCRIPT 回退次数）、限流 429 比例。
6. 应用侧已具备 NOSCRIPT 自动回退与连接故障 503 降级，无需额外组件。

### 7.6 独立答辩演示数据 Seed Script 方案

- **独立性**：写入独立演示库（如 `ssp_v3_demo`）或演示专用 `users`（`username` 前缀 `demo_`），绝不写入正式库；脚本带库名/前缀双重断言。
- **不产生真实 AI 费用**：`ai_requests` 历史记录直接以 INSERT 造数（状态 `DONE`、token 与耗时字段填合理假值），不调用 DeepSeek；Redis 不预置任何限流 key。
- **业务一致性**：
  1. `users` → `study_plans`（ACTIVE / ENDED 各一）→ `plan_steps`（含分支与叶子）→ `daily_tasks`（PENDING / IN_PROGRESS / COMPLETED，含跨日结转）；
  2. `task_rollovers` 与源/目标任务数量守恒；
  3. `study_records` 的打卡日期、数量与任务进度一致，连续打卡天数满足 streak 规则；
  4. `knowledge_notes` 与标签关联，`practice_records` 与笔记对应；
  5. `ai_requests` 时间落在近 7 天，与笔记/问答内容语义对应；
  6. `admin_audit_logs` 覆盖 BAN / UNBAN / REVOKE_SESSIONS / UPDATE_AI_CONFIG 四类动作，`admin_id` 指向演示管理员。
- **统计隔离**：演示用户带明确标记；所有统计脚本/报表按演示标记过滤，确保不混入真实用户统计。演示结束可一键按标记清理。
