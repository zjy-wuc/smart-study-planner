查询
这里的核心功能由res层实现，输入的有关键字，tag，学习计划 哪我们怎么在sql里面查找呢？这里就用到了动态sql条件拼接。这些条件都可以只有一个，哪就会有没有的情况。动态拼接我们的核心是两个部分：conditions和params，conditions负责处理搜索语句，if 有 keyword那么就append对应的查找语句，params就负责输入数据。

其中，有些语法：LOCATE(:keyword, title) > 0 查找子字符串的，找到就返回其位置"JSON_CONTAINS(tags, JSON_QUOTE(:tag)) = 1"
`JSON_QUOTE(:tag)` 会把传入的标签文本转换为合法的 JSON 字符串值 
```
JSON_CONTAINS
```
而这个就是用于判断 JSON 文档是否包含指定的 JSON 值

操作完后直接and连接

我们的查询还要查询两次，为什么呢？

番茄闹钟的后端业务逻辑
我们的闹钟支持正向计时和番茄闹钟倒计时，正向计时最多24h，而且这次闹钟的设计我们还运用了我们之前设定学习步骤就用到的：状态机 这也是我们今天闹钟运转的核心逻辑

从service看，从最重要的状态机函数
operate_session开始，它统一处理各种状态：pause  先计算专注时间（_elapsed_seconds依赖函数，给start，end，吐出秒），再更新数据库改状态  resume就恢复，数据库running_started_at记录现在时间
finish 先累计时间，再结束，cancel就直接focused=0了

其次是查看历史记录
这里的重点是在操作数据库时，它可以有页数。普通的展现就是一股脑全展示，但这个不同，有了page操作。
在limit时，会根据page size和offset=(page - 1) * page_size（跳过的记录）来寻找对应的记录，这就可以实现分页查询

最后一个重要函数就是_auto_settle（自动处理），这个函数会对当前传来的session进行处理，自动判断任务是否完成，
