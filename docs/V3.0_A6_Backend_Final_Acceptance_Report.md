## 四、Redis 精确滑动窗口补充验收

### 4.1 真实 NOSCRIPT 冷缓存恢复 — **PASS**

使用独立临时 Memurai（端口 6390、临时目录），启动前 `SCRIPT EXISTS` 为 false，调用真实 `check_ai_rate_limit()`：

| 检查点 | 实际结果 |
|---|---|
| 调用前 `SCRIPT EXISTS` | `False` |
| 首次调用触发 `script_load` | 1 次（捕获 NOSCRIPT 后的客户端自动恢复） |
| 首次调用后 ZSET 计数 | `ZCARD=1` |
| 脚本写入缓存 | `SCRIPT EXISTS=True` |
| 第二次调用 | `ZCARD=2`，`script_load=0`（复用缓存） |
| 共享实例脚本缓存 | 未执行 `SCRIPT FLUSH` |

```

PASS noscript-recovery script_load_calls=1 zcard=1 script_exists_after=True
PASS cache-reuse script_load_calls=0 zcard=2
PASS cleanup temp-instance
```

### 4.2 真实连接故障与恢复 — **PASS**

同一 FastAPI 应用进程贯穿三阶段，使用独立实例（端口 6391）：

| 阶段 | 验证项 | 实际结果 |
|---|---|---|
| 1 正常 | AI 准入成功 | PASS（Guard 准入 + SUCCESS 结算） |
| 2 停止 Redis | 新 AI 请求 | HTTP 503，`code=AI_RATE_LIMIT_UNAVAILABLE` |
| 2 | AI Provider 调用次数 | 0 |
| 2 | 普通学习业务 | `GET /notes` 200 |
| 3 重启 Redis | 无需重启 FastAPI | PASS（同进程再次准入成功） |

**部署影响**：Redis 进程重启或数据丢失会重置 60 秒限流窗口，期间用户可重新获得满额频率。若需跨重启严格限流，应启用 AOF/RDB 持久化并纳入运维要求；当前“临时实例无持久化”的行为已如实记录。

- 管理员写操作缺少 CSRF：403 `CSRF_REJECTED`。

- 个人资料更新携带 `role=ADMIN` 被忽略，数据库角色保持 `USER`；`UserCreate` schema 无 `role` 字段。

| SESSION_REVOKED / SESSION_EXPIRED | PASS | 均为 401，来源为会话查询 |
| ACCOUNT_DISABLED | PASS | 直接禁用但保留会话时 403 `ACCOUNT_DISABLED` |

| ADMIN_REQUIRED | PASS | 已认证但非管理员 403 |
